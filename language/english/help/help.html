Help: wgDeveloper

wgDeveloper

Administration and development utilities for XOOPS

Inspect and maintain your XOOPS installation with a database browser, SQL tools and a language-file checker, directly from the administration area.

XOOPS 2.7.3+ PHP 8.4+

Welcome

Welcome to the wgDeveloper help page. This module brings a set of tools for inspecting and maintaining a XOOPS installation into the administration area.

wgDeveloper is intended for site administrators and developers. It does not provide a public-facing module page.

The main areas of wgDeveloper are the database tools (table browser, record editing and SQL editor) and the language-file checker for finding unused or missing language constants in a module.
Warning: The database tools work directly on your data. Always create a verified database backup before changing, truncating or dropping anything.

Getting Started

After installing wgDeveloper, open the module from the XOOPS administration area.

  1. Open Administration → Modules.
  2. Open wgDeveloper.
  3. Check the dashboard and the module settings.
  4. Use the database tools or the language checker for your task.
  5. Always create a backup before changing data.
Recommended workflow: Use the browsing and inspection functions first. Only edit, delete, truncate or drop after you have checked the affected table and created a backup.

Dashboard

The administration dashboard is the starting point of the module and gives quick access to all available tools.

Whether feedback information is displayed on the dashboard can be switched on or off in the module settings.

Database Tools

The database tools allow you to look into the database of your XOOPS installation without an external tool.

Available functions

  • List tables – show the database tables.
  • Inspect columns – show the structure of a table.
  • Browse records – list and view records of a table.
  • Edit or delete records – change or remove single records.
  • SQL editor – execute your own SQL statements.
  • Truncate or drop tables – empty or remove complete tables.
Important: Database changes can cause data loss or leave modules in an inconsistent state. Prefer the administration functions of the respective module for routine content management.

Tables & Columns

The table list shows the tables of the database. For each table you can open the column overview.

The column overview contains the following information:

Information Description
Type The data type of the column.
Nullability Whether the column accepts NULL values.
Key Whether the column is part of a key or index.
Default The default value of the column.
Extra Additional attributes, for example auto increment.

Truncate and drop

  • Truncate removes all records of a table, the table itself remains.
  • Drop removes the table completely, including its structure.
Caution: Truncating or dropping a table cannot be undone. Never do this with tables of the XOOPS core or of installed modules unless you know exactly what you are doing.

Records

Open a table to browse its records. You can view the details of a single record and, if necessary, edit or delete it.

  • Browse – list the records of the selected table.
  • View – show all values of one record.
  • Edit – change values of one record.
  • Delete – remove one record.
Important: Deleting or editing records directly bypasses the logic of the module that owns the data. Related data (for example uploaded files or entries in other tables) is not updated automatically.

The number of entries per page in the administration lists can be configured in the module settings.

SQL Editor

The SQL editor lets you execute SQL statements against the database. For a selected table the available columns can be displayed, which helps when writing statements.

  1. Open the SQL editor.
  2. Select a table to see its columns, if needed.
  3. Enter your SQL statement.
  4. Check the statement carefully.
  5. Execute the statement.
Caution: Statements such as UPDATE, DELETE, TRUNCATE or DROP change data permanently. Always create a backup first and test statements on a copy of your site whenever possible.

Language Checker

The language checker helps developers to keep the language files of a module clean. It scans the English language definitions of a selected module and checks whether each definition is used elsewhere in that module.

How to use

  1. Open the language checker.
  2. Select the module you want to check.
  3. Choose whether all results or only warnings should be displayed.
  4. Start the check and review the result.

Display options

  • All results – show every checked language definition.
  • Warnings only – show only definitions that need attention.
The checker uses the files in language/english of the selected module as its source. Constants that are built dynamically at runtime may be reported as unused even though they are needed. Please review the results before removing anything.

Module Settings

The module configuration can be accessed through the XOOPS module administration.

Administration

  • Pagination – number of items per page in administration lists (10, 25, 50 or 100).
  • Dashboard feedback – show or hide the feedback information on the dashboard.

Meta information

  • Meta description – description used for the module.
  • Keywords – keywords associated with the module.

Permissions & Security

wgDeveloper is an administrator tool. Access to the module should be limited to trusted users with appropriate XOOPS administration permissions.

Security recommendation: Do not grant access to wgDeveloper to untrusted user groups. The module exposes low-level database operations. If you only need it temporarily, consider deactivating or uninstalling the module on production sites after use.

Typical Use Cases

wgDeveloper can be used for many different maintenance and development tasks:

  • Checking the structure of a database table
  • Looking up the content of a record
  • Fixing a single wrong value in a record
  • Emptying a table during development or testing
  • Cleaning up tables left over from removed modules
  • Running a quick SQL query
  • Finding unused language constants in a module
  • Finding missing language constants in a module

Troubleshooting

The module is not visible in the administration

  • Check that the module is installed and active.
  • Check that the directory is named wgdeveloper.
  • Check the administration permissions of your user group.
  • Clear the XOOPS cache if necessary.

An SQL statement fails

  • Check the syntax of the statement.
  • Check the table and column names, including the table prefix.
  • Check whether the database user has the required rights.

The language checker shows unexpected results

  • Check that the selected module has a language/english folder.
  • Check whether constants are built dynamically in the module code.
  • Switch between "all results" and "warnings only" to compare.

Installation & Requirements

wgDeveloper is a XOOPS module and uses the standard XOOPS module installation and update mechanism.

Component Minimum Version
XOOPS 2.7.3
PHP 8.4
ModuleAdmin 1.2
MySQL / MySQLi 5.6
  1. Download or clone the repository.
  2. Make sure the module directory is named wgdeveloper.
  3. Copy the directory into the modules folder of your XOOPS installation.
  4. Open Administration → Modules and install wgDeveloper.
  5. Open the module's administration area.
Updating: Before updating an existing installation, back up the database and the module files, then follow the normal XOOPS module update procedure.
